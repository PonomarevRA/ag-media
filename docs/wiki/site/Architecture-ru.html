Архитектура

Архитектура и границы ответственности

Браузер отвечает за рабочие поверхности и отображение результатов. HTTP/MCP принимают запросы. Оркестраторы выбирают необходимые стадии и запускают workers. Граф хранит компактные связи, таймкоды и происхождение; он не заменяет исходный файл.

web/ → HTTP app/server.py → speech/ + vision/ + audio/
                         → graph/ → timeline / MCP
synthesis/ ← speaker samples + prosody/ → WAV / dubbing
core/ → budgets, locks, stages, cache lifetime
workers/ → isolated model processes

Правила связи модулей

  • Точка входа в корне совместима со старым клиентом, реализация живёт в voice_studio/.
  • UI и экспорт должны переиспользовать общую модель технического слоя; иначе появляются отличающиеся рамки и подписи.
  • Связь спикер–лицо хранит основание. Видимое лицо, активное говорение и номер спикера — разные виды свидетельств.
  • Один предмет может иметь много наблюдений и несколько исходных меток. Профиль не должен удалять исходные уверенности и рамки.
  • Таймкоды относятся к исходнику. При обработке чанков локальные времена должны переводиться в общую шкалу.
  • Модельные окружения, весовые файлы, пользовательские данные и временные кэши не становятся частью wiki.
